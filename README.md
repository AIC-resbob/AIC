# StockFlow AI

AI inference system for UMKM/retail inventory: predicts restock needs before a product runs out,
and recommends clearance discounts for overstocked items — with an explicit probability that the
discount actually clears the stock in time, while keeping the sale price above cost.

**Category:** Smart Commerce & Smart Logistics

## Features

- **Fitur A — Smart Restock Predictor.** From the last 30 days of sales for a SKU, predicts total
  demand for the next 7 days and converts that into a restock quantity recommendation (with a
  service-level-based safety stock buffer).
- **Fitur B — Discount Engine.** For a slow-moving / overstocked SKU, sweeps candidate discount
  percentages and — for each one — predicts the probability the stock clears within a target
  number of days and the expected profit, while enforcing `harga_jual >= cogs` (sale price never
  drops below cost) as a hard floor.

## Model selection

Both features compare multiple candidate models (naive/linear baselines, Random Forest,
HistGradientBoosting, LightGBM) and tune the strongest gradient-boosting candidates with Optuna.
The final production model for each feature is **selected programmatically from the lowest test
error** (WAPE for Fitur A, Poisson deviance for Fitur B) — not hardcoded — so re-running the
notebook always deploys whichever model actually wins on the numbers. See Section 9 of the
notebook for the full comparison tables and rationale.

### Generative structure (ground truth)

```
demand ~ Poisson(lambda)

lambda = base_demand
    x day_factor
    x payday_factor
    x ramadan_factor
    x trend
    x (harga_jual / harga_normal) ^ elasticity
    x lognormal_noise(0, 0.14)
```

**Day factor:** Mon 0.88 - Tue 0.90 - Wed 0.95 - Thu 1.00 - Fri 1.15 - Sat 1.32 - Sun 1.20

**Payday factor:** 25th-31st -> 1.28, 1st-5th -> 1.18, 6th-10th -> 1.02, otherwise -> 0.92

**Ramadan factor:** ramps up toward Eid, then drops to 0.65 for a week afterward.

### Modelling notes

- **Don't use `harga_normal` as the price feature.** What actually drives demand is
  `harga_jual`; the correct elasticity variable is the ratio `harga_jual / harga_normal`.
- **Watch for endogeneity.** Discounts are often triggered by high stock / near-expiry, not
  randomly. A naive regression will be biased — control for `hari`, `is_periode_gajian`,
  `is_ramadan`, and a time trend (this is what brings elasticity-recovery MAE down from 0.197 to
  0.166).
- **`quantity_sold` is stock-censored.** When stock runs out, sales are truncated and true demand
  is recorded in `lost_sales`. For demand estimation, drop `stock_akhir == 0` rows or use
  `quantity_sold + lost_sales`.
- **Split train/test temporally**, not randomly, e.g. train on 18 Aug 2025 - 17 Jul 2026, test on
  18 Jul - 17 Aug 2026. A random split leaks the future into the past and inflates the score.
